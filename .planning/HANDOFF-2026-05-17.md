## Two open conceptual issues the user raised

The user asked these as rubber-ducking questions, not work-tickets. They'll likely come back with direction after manual review. Don't pre-emptively implement either — surface them when relevant.

### 1. TOKEN vs PRIMITIVE — the schema is internally inconsistent

Working definition the conversation landed on:
- **Token** = a raw value or a generative recipe for a value. Pure data. CSS custom property, possibly parameterised. Examples: `--ink-3`, `--note-do`, `--dur-tap`, `--ease-swing`, `--beat`.
- **Primitive** = the smallest renderable thing. Markup + CSS that *consumes* tokens and has its own visual identity + states. Examples: `.knob`, `.kicker`, `.tile`, `.beat-pulse` utility class.

By that rule, three cards are misplaced because the filename prefix tricked the bucketer:
- `mot-primitives-durations.html` → should be TOKEN/motion (documents `--dur-*`)
- `mot-primitives-easings.html` → should be TOKEN/motion (documents `--ease-*`; the runner dot is a presentation device, not a primitive)
- `ease-run-demo` atom → specimen-internal apparatus, same category as the already-acknowledged `ease-dot`. Should be flagged as style-guide-internal, not promoted as an app primitive.

If the user wants this cleaned up, it's a rename-only fix (move three cards across the line, drop the fake `demo-runner` family). The card HTML doesn't need to change.

### 2. Hardware bar (and other PARTs) are under-decomposed

`components-chip.html` is bucketed PART/chips with `consumes: [transport-row, meta-anno-row]` — but the card actually contains: instrument label, key indicator, BPM display (label + 7-segment numeric `.seg`), beat counter, VU meter, scrubber, status LED dots. `atoms.json` even has a note on `transport-row`: *"actually 7 sub-atoms — split during promotion"*. The split never happened.

Other PARTs with the same under-statement (their CONSUMES rows under-list the assembly):
- `panel-header-with-tape` — badge + meta-anno-row + icon-row + chromatic-tape (the tape may be `bar-tape` atom)
- `code-strip-notation` — play head + syllable cells + timestamps + transport buttons
- `pattern-card` — spine + ordinal + metadata + mini-roll

Also genuinely missing from atoms.json (flagged in `_meta.unresolved` of `unification-data.json`): `badge`, `bar-tape`, `durations`, `brand-pattern`, `brand-stickers`.

If the user wants to tackle this, it's bigger than Phase 4/5 — it's a Phase 3.3 "second-pass decomposition" that updates atoms.json AND adds primitive specimen cards for the split-out atoms.
