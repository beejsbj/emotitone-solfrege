# Design System Plan

Current truth and executable queue for the temporary EmotiTone production visual-design pass. Read this file with `$emotitone-design-system`; use `DESIGN_LOG.md` only for chronological receipts and Git for archaeology.

## Mission

Tighten and promote the visual language already present in production, `/style-guide/`, and the reference material. Burooj is the taste authority where evidence leaves a real visual choice. Reconcile drift and lineage without redesigning the product from zero.

This is a visual-system migration. Preserve interaction, audio, routing, state, persistence, APIs, accessibility behavior, haptics, and motion unless a unit's accepted definition expressly changes them. Park standalone functionality and defects outside this pass.

## System model

```text
Tokens (foundations)
  -> Primitives (reusable elements)
    -> Compounds (reusable assemblies)
      -> Compositions (complete product surfaces)

Uniques (singular artifacts, orthogonal to complexity)
  -> may be primitive-like or compound-scale
  -> may consume appropriate reusable layers and feed compounds/compositions
```

`Unique` is not a rung between Primitive and Compound. It identifies an artifact that should remain singular rather than become a reusable family. Ordinary uniqueness does not make every Primitive a design-system `Unique`.

Every reusable visual rule has one lowest appropriate owner and is consumed upward. A guide-only specimen proves the rule can render; it does not prove production adoption. A token with no consumer outside its own token showcase is an orphan until it is adopted, merged, removed, or explicitly retained with a reason.

## Records, truth, and gates

There are two durable records:

- This file is the **Plan**: live definitions, status, dependencies, collision points, and next gates.
- `DESIGN_LOG.md` is the **Log**: append-only acceptance, implementation, verification, and handoff receipts.

Do not create a third planning ledger. Keep completed implementation narrative, commit lists, and old verification matrices in the Log, Git, or existing evidence directories; keep only decisions that still constrain future work here.

When sources disagree, use this order: Burooj's current instruction, this Plan, current production and observed behavior, the Log, Linear `BJS-35`, then Git history. The external design repository, old preview HTML, screenshots, and guide staging are reference evidence rather than acceptance authority.

Each unit tracks four independent gates:

1. **Defined** — Burooj accepted the shared visual definition.
2. **Authoritative source** — one source owns the accepted grammar.
3. **Real specimen** — `/style-guide/` imports and drives that source.
4. **Production adoption** — a real product surface consumes that source.

Work from a focused branch based on the current mainline, normally the latest `origin/main`. Recompute branch, worktree, ahead/behind, test, and preview state at session start; never cache those facts here. One branch should contain one coherent unit or one coordinated lower-layer promotion.

## Governing constraints

- Brand colors are decorative; brass is an instrument material. Semantic aliases such as `--danger` are legacy cleanup, not design doctrine.
- Prefer filled surfaces and minimize borders. An outline must be intentional visual grammar rather than default structure.
- Glassmorphism remains rejected. Keyboard Glass/Opacity, Roundness, and Angled Style controls are retired; do not restore them through token cleanup or later compositions.
- Drawer uses its accepted exposed-edge icon/grip handle. Do not reintroduce the retired floating triggers or Drawer Boolean Knob.

### Accepted UIBeat protocol

- **Authority and coordinates:** one bridge exposes a transport generation, playback state, raw scheduler position, sounding-tempo/mapping availability, and—only when authoritative—zero-based bar and beat indices, normalized beat phase in `[0, 1)`, and meter numerator/denominator. Raw Strudel cycles do not silently become bars. The verified production V1 mapping is generated 4/4 playback; richer meters remain isolated guide fixtures until runtime meter authority exists. Configured BPM and arbitrary edited-code tempo are not interchangeable, and an unavailable mapping stays unavailable rather than being fabricated.
- **Lifecycle:** fresh Play arms presentation until the first valid frame; joining an existing run samples its current phase. StrudelMirror evaluations serialize, callback-reported evaluation errors propagate through the evaluation promise, stop the actual scheduler, and generation-guarded callback cleanup cannot retire a later queued run. A separate monotonic evaluation epoch wraps the StrudelMirror Stop boundary used by native editor and attached-controller actions, invalidates queued playback intent on Stop, sample warmup, or component teardown, and re-stops an in-flight evaluation if it settles after cancellation without discarding a newer post-Stop Play. The controller reports canceled evaluation explicitly; shared Play state also verifies controller and request identity before committing, so stale completion, error, or detach cannot overwrite its successor. Evaluation, editor replacement, and genuine scheduler restart create a new UIBeat generation, so stale callbacks cannot resurrect motion. Stop, detach, error, audio suspension, and hidden-tab return produce no queued catch-up pulses; bound elements return directly to identity when presentation stops, while a resumed or re-enabled element joins the current phase.
- **Tempo and grouping:** consumers sample authoritative phase instead of launching independent duration loops. Generated playback normalizes Strudel's scheduler CPS to the generated bar rate before `.cpm` evaluation, making one scheduler cycle the shared sounding/UI bar coordinate. A BPM change uses Cyclist's own continuous-cycle `setCps` seam and retimes the current UIBeat generation before re-evaluating the matching unit-rate pattern, so both audio and presentation change speed without a zero reset or persistent phase offset; only a genuine scheduler reset begins a new generation. V1 groups are bar/downbeat, beat, and meter slot; a slot follows the meter unit, while arbitrary subdivision recipes remain excluded. This restriction deliberately trades ornamental off-beat motion for legibility and bounded distribution.
- **Consumer seam and ownership:** one disposable registration seam and one pooled `IntersectionObserver` per clock serve production consumers; element-indexed subscribers retain independent offscreen suspension and release observation after the final subscriber leaves. One injected provider pairs the clock with presentation policy: `MainApp.vue` owns the production Visuals/UIBeat gate, while the guide supplies an isolated deterministic provider and never attaches to production playback. UIBeat owns time, state, grouping, coordination, and the accepted normalized BeatingShapes-derived contour. Button binds its inert paper face, Knob binds its visual face, and Joystick binds an inner visual assembly; native Button and Joystick interaction surfaces remain unscaled. Disabled/loading Button plus disabled Knob decline the binding. Sticker stays default-false for selected-current-instrument use. The general `bindUIBeatScale` / `useUIBeatScale` seam writes only the CSS individual `scale` property, never layout geometry, decorative halo, opacity, or the element's `transform`, so Button press, Knob drag/rebound, Joystick stick motion, Sticker rotation, and other transforms compose. Joystick pointer gain reads unscaled layout dimensions rather than beat-scaled client bounds. Duplicate UIBeat ownership of one element throws. A target that already owns the individual `scale` property must expose a different real containing node or explicitly coordinate that property; `DragValue` therefore remains excluded.
- **Enablement and stillness:** UIBeat and the global Visuals gate affect presentation only; audio and logical transport continue. Re-enabling joins current phase. Reduced Motion immediately removes all recurring transform and opacity change without rewriting the persisted preference; no opacity-blink fallback remains. Beat Indicator owns its accepted stationary idle/downbeat emphasis.
- **Performance budget:** Accepted UIBeat distribution reaches Beat Indicator, every enabled Button and Knob, Joystick, and the selected current-instrument Sticker. Runtime uses one shared scheduler/frame bridge, no per-consumer timers or frame loops, no frame-loop layout reads, one pooled visibility observer, and only compositor-friendly transform, individual scale, and opacity for recurring motion; hidden/offscreen registrations suspend. Built production in a visible Google Chrome 147 Xvfb window counted 11/11 running controls at both 1366×768 and a 412×915 DPR 2.625 viewport (6 Buttons, 4 Knobs, 1 Joystick), and 16/16 with Config open (10 Buttons, 5 Knobs, 1 Joystick). Equal-window UIBeat on/off/on comparisons in the software-rendered accepted scene showed no clear incremental task, style, or frame penalty, but the canvas workload and virtual display were too noisy for a frame-budget claim. Named physical desktop/mobile devices with native visible-tab whole-frame pacing remain an explicit residual verification gate.
- **Migration:** a new UIBeat setting wins over legacy data; legacy `BeatingShapes.isEnabled` seeds it only when the new value is absent, across current storage, saved scenes, imported configurations, resets, and bundled presets. Preserve the global Visuals gate. Retire BeatingShapes, its `UnifiedVisualEffects` mount, geometry-specific opacity/scale/count/saturation/glassmorphism fields, arbitrary hue cycling, and fixed beat-duration tokens as runtime authority. The Motion guide must use the isolated UIBeat clock and remove its literal independent loops and Reduced Motion blinking. Config/preset and `UnifiedVisualEffects.vue` changes stay serialized with their owning lanes.
- **Control-family adoption proof:** Beat Indicator proves bar/slot semantics; every enabled Ring/Arc Knob face and Button paper face inherits the source-owned default; Joystick proves an inner visual-assembly scale whose outer pointer surface, stick motion, and gesture calibration remain independent; and the selected current-instrument Sticker proves a deliberately narrower cut-paper policy without replacing randomized rotation. The Sticker means the current instrument participates in the interface's playback pulse, not that arbitrary sounding code necessarily contains that instrument. The isolated guide mounts those real sources, controls its Joystick state, and exercises both accepted Knob editions. Each consumer maps the shared contour without a local timer or duplicated composition policy.

The Motion guide now delegates tempo and meter to UIBeat's isolated clock, preserves current musical position when tempo changes, resets deliberately when meter changes, removes the old square `beat-cell` and global fixed-BPM loops, and becomes fully still under Reduced Motion. Already accepted local recipes such as rip-mode and Drawer Swing remain constrained evidence, not automatic acceptance of the full collection.
