# Runtime workload and Stage guard

`runtime-guard.mjs` supplies a dependency-free browser function for the CDP capture. Install it in the measured page's main execution context after scene preparation and keep it installed through the complete on/off/on run. `runtimeGuardInstallerExpression(options)` returns the expression to assign to a page-global handle.

For each measured window, call `start({ label, expectedDurationMs, maximumCanvasIdleMs })`, run the sample, then call `snapshot()`. Call `stop()` in capture cleanup and retain its report even when an earlier step failed. A usable capture requires every window and the final session report to be valid.

`stop()` attempts active-window finalization and the final workload read, then marks the guard stopped before independently removing every observer, subscription, event listener, and owned canvas wrapper. Read and cleanup failures make the returned report invalid and remain serialized in its `errors` array with their phase, name, and original message; one failure cannot skip later cleanup.

The guard synchronously subscribes to the production Pinia workload, listens for operator `input`/`change` events, and compares aggregate semantic DOM values after CodeStrip or stable-control mutations. Separate input events retain changed-then-restored CodeStrip edits even when both arrive in one observer batch, while synchronous Pinia subscriptions retain transient effective Stage Looks and restored store controls. Only `effectiveConfig.uiBeat.isEnabled` and its Global control are excluded because the capture deliberately changes UI Rhythm. Style/class animation, CodeMirror's same-text syntax-highlight churn, active notes, playback progress, and other ordinary motion do not alter the fingerprint.

An arbitrary script that changes and restores DOM text in one microtask without dispatching input, change, or a store mutation is outside this guard's observability: its mutation batch is indistinguishable from CodeMirror's normal same-text decoration work. The physical procedure excludes such automation during measurement.

The retained production `.code-strip-bar__play` control supplies UI transport state through its Play/Stop accessible name. A stop and restart invalidates the session even when the final state is Stop again. This proves continuity of the application's declared UI transport state; it does not directly inspect the audio device or speaker output.

The Config handle identified by `config-panel-trigger` anchors one retained top Drawer. Its root height, content height, root expansion, and handle expansion are part of the workload fingerprint. Dedicated attribute observers watch only those retained geometry nodes and preserve changed-then-restored values from mutation old values. They do not observe descendant class/style animation, including UIBeat face scale. Pending workload records are drained before each window snapshot and final cleanup.

The retained PerformanceDeck supplies Stage geometry through the same production contracts as `useStageHostLayout`: its `[data-stage-occlusion-host]`, `[data-stage-occluder]`, and visible `[data-stage-occlusion-part]` bounds determine a source-derived usable rectangle. Every successful clear samples that rectangle. Each window requires complete samples, no width or height below the production 150px suspension threshold, and no geometry or occlusion-state change. Narrow observers on the deck root, content, and occlusion parts retain a resize or reel-geometry change even when it is restored between clear samples. The reported rectangle is independently derived from the production DOM contract; it is not access to Vue's private `usableRect` ref.

The workload also retains the resolved `prefers-reduced-motion` media-query state. Its change listener stays armed through on and off windows, so changing and restoring the OS/browser preference invalidates the session even though that preference is outside Pinia.

The Stage heartbeat wraps only `clearRect` on the retained `.unified-canvas` 2D context. It counts a heartbeat after a successful full-canvas clear, matching the entry of `useUnifiedCanvas`'s production render frame. Every window must cover its requested duration with at least two successful clears and no leading, internal, or trailing gap above `maximumCanvasIdleMs`. Canvas replacement, disconnection, context replacement, `contextlost`/`contextrestored`, or a context reporting itself lost invalidates the window.

The wrapper adds one timestamp append, four argument comparisons, and source-derived Stage geometry reads to each successful production clear while a window is active. These layout reads add measurement overhead. The wrapper preserves the original receiver, arguments, result, and thrown errors. `stop()` restores the exact prior own property descriptor, or removes the owned instance wrapper when the method was inherited. If another actor replaces the wrapper, cleanup reports lost ownership and leaves that replacement untouched.

This heartbeat proves continued entry into the production Stage render loop and its successful canvas clear. It does not prove that every effect painted content, that Chromium composited each frame, or that a physical panel displayed it; the capture's pacing, renderer, trace, and operator evidence remain responsible for those claims.
